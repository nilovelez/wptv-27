WordPress.tv RSS Feed

Every element of https://wordpress.tv/feed/, what it contains and who produces it: WordPress core, the WordPress.com platform, VideoPress or the theme. Use it to know what the next version may change and what other tools rely on.

Checked: October 22, 2026 Production: 50 items parsed, served by wptv2 New theme: wptv-27 on an empty WordPress 7.1.3 review site

Key facts

50items per feed in production (posts_per_rss), newest first
2media:content per video: the VideoPress video and the original upload
40 / 50items with the "Presentation Slides" link in description
3places where the theme changes the feed, all ported unchanged

Who produces each element

core

WordPress core feed template (feed-rss2.php). Same on any WordPress site.

wpcom

Added by the WordPress.com platform. Absent on a plain WordPress or Studio site.

videopress

Video data from VideoPress, through the [wpvideo] shortcode and Media RSS.

theme

Changed by the theme: wptv2, ported unchanged to wptv-27.

Element tree

Brackets give how many times an element appears: [1] once, [0..n] any number, [0..50] up to the feed size. Attributes follow the tag with @.

Inside content:encoded

For a clean video post (its content is one [wpvideo] shortcode), WordPress.com renders the shortcode into the same three pieces in all 50 production items.

1

Player iframe

The VideoPress embed at feed size, 400 × 233, with the player options as query parameters.

<iframe title='VideoPress Video Player' aria-label='VideoPress Video Player'
        width='400' height='233'
        src='https://video.wordpress.com/embed/{GUID}?hd=1&autoPlay=0&permalink=1&loop=0
             &preloadContent=metadata&muted=0&playsinline=0&controls=1&cover=1'
        frameborder='0' allowfullscreen allow='clipboard-write; presentation'></iframe>
2

Player script

Loads the VideoPress iframe API.

<script src='https://v0.wordpress.com/js/next/videopress-iframe.js?m={version}'></script>
3

Linked thumbnail

A fallback for feed readers that strip iframes and scripts: the poster at 160 × 120, linking to the video page. Its alt is the video attachment title.

<div><a href="{permalink}"><img alt="{video title}"
  src="https://videos.files.wordpress.com/{GUID}/{file}_mp4_std.original.jpg"
  width="160" height="120" /></a></div>
Anything else in the post content follows these three pieces.

That is why the pre-migration cleanup (Tools → Moderation tools → Post content to clean) matters for feed readers too: stray text and empty paragraphs end up in content:encoded.

The two media:content elements

Every production item carries both, in this order. Media RSS (xmlns:media="http://search.yahoo.com/mrss/") only exists on WordPress.com.

1 · The VideoPress video

videopress
@width, @height
Feed player size, e.g. 400 × 233. No @url or @medium here.
media:player
@url="https://videopress.com/v/{GUID}"
media:rating
@scheme="urn:mpaa", value such as g
media:title
@type="plain". The title of the video attachment, not the post. The theme keeps it in sync with the post title when it was the default or the previous title.
media:thumbnail
@url @width @height, the VideoPress poster, e.g. …_mp4_hd_1080p.original.jpg at 256 × 149

2 · The original upload

theme
@medium
video
@isDefault
false
@url
The file uploaded through the submission form, e.g. https://wordpress.tv/wp-content/uploads/YYYY/MM/video-{random}.mp4
Source
Added by the theme through the mrss_media filter, only when the post has a video attachment
Also removed
The author avatar that WordPress.com adds to each item (mrss_avatar_user filter), since every video belongs to the anonymous upload user

wptv-27 compared with wptv2

Same structure and fields. The theme changes the feed in only three places, all ported unchanged:

  • the "Presentation Slides" link appended to description (inc/content.php);
  • the original upload as the second media:content (mrss_media filter);
  • the author avatar removed from Media RSS (mrss_avatar_user filter).

Everything tagged wpcom or videopress comes from the platform and does not depend on the theme. On a plain WordPress site the feed has only the core elements, and content:encoded holds the raw [wpvideo] shortcode.

Known difference

For posts converted to the VideoPress block, content:encoded renders the block player instead of the shortcode iframe, and its posterUrl parameter carries the featured image, as the approved poster decision requires. The latest route regression found exactly this difference in four feeds.
