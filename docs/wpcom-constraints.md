# WordPress.com platform constraints

WordPress.tv is a site on the **WordPress.com multisite**, not a standalone install. This shapes every technical decision.

## Hosting and access

- The site runs on WordPress.com infrastructure, in the main .com multisite.
- The theme source lives in an internal repository behind a proxy that only Automattic employees can reach.
- External contributors work from a mirror of that repository, which is refreshed on request (this takes time).
- Deploys are done by a WordPress.com employee. There is no direct access to production code, logs or the database.
- `wptv2` was uploaded as an exception: custom themes are not normally allowed on the multisite.

## Plugins

- **No custom plugins can be installed.** Only plugins already available on the multisite can be used.
- Therefore every site-specific feature (taxonomies, endpoints, forms, admin tools) must live in the theme.
- Plugins confirmed available (active on the local copy, mirroring production): Jetpack, Jetpack VideoPress, Layout Grid, Akismet.
- ⏳ Full list of multisite plugins: pending (see [open-questions.md](open-questions.md)).

## VideoPress

- Hosting is unlimited.
- Videos are embedded in post content with the `[wpvideo <guid>]` shortcode.
- On WordPress.com, the theme uses internal VideoPress helpers that **do not exist** in Jetpack or in local environments:

| Function / class | Used for |
|---|---|
| `video_get_info_by_guid()` | Video details (duration, size, rating, attachment ID) |
| `video_get_highest_resolution_image_url()` | Video thumbnails |
| `video_url_by_format()`, `video_highest_resolution_ogg()` | Download links, JSON-LD `contentUrl` |
| `video_get_single_response()` | File formats and HLS detection |
| `find_all_videopress_shortcodes()` | Finding the video GUID in content |
| `VideoPress_Subtitles`, `VideoPress_Subtitles_Track` | Subtitle tracks and languages |

**Rule:** always call them behind `function_exists()` / `class_exists()` and degrade gracefully (hide the section and return empty data, never fatal).

## Other WordPress.com-only APIs

| API | Notes |
|---|---|
| `bump_stats_extras()` | Internal stats. `wptv2` defines an empty stub when it is missing. |
| `jetpack_is_mobile()`, `Jetpack_User_Agent_Info` | Used by the dropped `widont` filter. |
| `mrss_avatar_user`, `mrss_media` filters | MediaRSS feed generated by WordPress.com. |
| `pre_option_blog_upload_space` | Upload quota (the theme sets it to 25 TB). |
| `is_super_admin()` | On WordPress.com this means Automattic staff. |
| `wptv_post_views` meta | Filled by WordPress.com stats. Not updated locally. |

## Local development caveats

- The local Studio site uses SQLite and runs Jetpack and VideoPress, but without the WordPress.com internals listed above. Thumbnails, downloads, subtitles, JSON-LD video data and Open Graph video tags cannot be fully tested locally.
- The local content was imported, so **IDs differ from production**. Never hardcode term, post or user IDs. Use slugs.
- Classic menus are empty locally and the `/subtitle/` page does not exist locally.
